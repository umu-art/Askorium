Современные системы поиска все чаще используют гибридный подход, комбинируя лексические sparse-методы (например, BM25) с семантическими dense-методами на основе трансформерных эмбеддингов. Такой гибрид позволяет сделать прорыв в полноте (recall) поиска: трансформеры лучше улавливают смысловые соответствия, но могут пропускать точные совпадения терминов, тогда как BM25 отлично находит точные совпадения по ключевым словам, но не понимает синонимы и перефразирования. Такой подход называется Hybrid Dense-Sparse Retrieval, в нем возникают сложности со слиянием результатов (fusion фаза):  относительно быстрые способы типа CSC или RRF дают точность ниже, по сравнению с чистыми dense-методами. Для этого применяется финальная фаза - reranker, cross-encoder трансформеры, умеющие оценивать насколько данный кусок текста может быть ответом на определенный вопрос, и это все вместе дает отличный результат.

Для точного ранжирования можно тестировать: T5, BERT, BGE-M3 + пробовать их урезанные версии. Поставленный нами верхний порог по времени для “быстрого“ режима поиска - 0.5 сек.

### Нормализация текста будет состоять из:

- Стандартизация слов
- Раскрытие сокращений и спецлексики домена
- Урезание бессмысленных минус-слов
- Расширение синонимами

## Итого общий пайплайн для реализации:

- Подготовка документов для поиска:
    - Нормализация текста
    - Бахаем overlap
    - Дополнение данных потенциальными вопросами через doc2query
    - Генерация эмбеддингов под dense-search
    - Сохраняем все это в:
        - sparse-index content и doc_queries
        - dense-index content и doc_queries
        - json хранилище для метаданных и выдаче ответа юзеру, линкуем по id
- Подготовка запроса:
    - Нормализация текста
    - Расширение генерацией сопутствующих широких запросов
- Retriever:
    - n from BM25 (лексический алгоритм)
    - n from BGE M3-Embedding (векторный поиск по эмбеддингам)
- Fusion:
    - Convex score combination 2n → m
- Reranker:
    - Cross-Encoder трансформеры вида BGE-reranker-v2-m3 с дополнениями:
        - Early Exit внутри Cross-Encoder, если релевантность уже точно ниже порога - скипаем вариант и не вычисляем ее дальше
        - Предварительный Comparing Multiple Candidates - загоняем батч документов на один запрос
- Комбинирование с метаданными и выдача результата
- Сторонняя LLM для реализации RAG
